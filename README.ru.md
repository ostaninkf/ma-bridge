# ma-bridge — голосовой мост Алиса → Music Assistant

Форк [rodyatotu/soundya](https://github.com/rodyatotu/soundya): к голосовому управлению soundya
добавлен бэкенд **Music Assistant**. Говоришь «Алиса, включи …» — играет из твоей библиотеки
Music Assistant, с учётом падежей и транслита; если точного совпадения нет — предлагает похожие
песни или поиск на Spotify. SoundCloud остаётся, если его назвать. Работает на
рутованной Яндекс-Станции как плагин [Luna](https://github.com/nyakokitsu/luna) (или автономно).

> Неофициальный проект. Не связан с Яндексом, SoundCloud, Home Assistant и Music Assistant.

## Что делает

Голосовой слой soundya (`src/alice.rs`) перехватывает распознанную Алисой фразу на
`127.0.0.1:9875` и превращает «Алиса, включи …» в интент. Форк его маршрутизирует:

| Фраза | Куда |
|---|---|
| «Алиса, включи **Кино** / **Агату Кристи** / **белую ворону**» | **Music Assistant**, только локальная библиотека (см. [Локальный поиск](#локальный-поиск)) |
| «Алиса, включи **музыку**» (генерик) | **Music Assistant** (продолжить или запустить волну/диджей) |
| «Алиса, включи Кино **в саундклауде**» | SoundCloud (как в оригинале) |
| «пауза / дальше / что играет / громче» | активный источник (MA или SoundCloud) |
| «… **в яндекс музыке**» | родная Алиса (без изменений) |

Мост сам звук не тянет — он зовёт **REST API Home Assistant** (`music_assistant.play_media` +
`media_player.*`), а Music Assistant играет на плеере-колонке своим провайдером. Явное «включи X»
играет ровно это, без `radio_mode`; бесконечный «диджей»-поток — только на «включи что-нибудь
похожее / порекомендуй».

Реализовано для MA: воспроизведение (исполнитель/трек/альбом/плейлист),
пауза/продолжить/дальше/назад, перемотка, перемешивание, повтор, громкость, «что играет»,
«похожее/рекомендации» (волна по текущему исполнителю), генерик «включи музыку» (продолжить;
диджей не запускает никогда).

## Локальный поиск

«Включи X», «включи альбом X», «включи плейлист X» ищут **только в локальной библиотеке** Music
Assistant. Собственный поиск MA ищет подстроку и спотыкается на живой речи («включи Агутина» →
«агутина» не подстрока «Агутин»), поэтому мост держит свой индекс и сопоставляет сам
(`src/local.rs`):

- **Индекс** — `music_assistant.get_library` по артистам, альбомам, трекам и плейлистам (~3,5 с на
  2700 элементов), в памяти колонки; перестраивается в фоне раз в 15 мин и по промаху, если ему
  больше 5 мин. Локальным считается только то, у чего есть треки: артисты/альбомы, втянутые
  импортом из стримингов без своих треков, пропускаются; служебные плейлисты MA и плейлисты
  чужих сервисов — тоже.
- **Сопоставление** — обе стороны в латиницу; слово совпадает точно, в другом падеже (общая
  основа, оба хвоста из списка русских окончаний) или — только кириллица против латиницы — по
  скелету согласных («квин» → Queen, «элтона джона» → Elton John, «битлз» → The Beatles).
  Инициалы — по первой букве («булата окуджаву» → «Песни Б. Окуджавы»); украинские буквы
  приводятся к русским («иконы не плачут» → «Ікони не плачуть»). «Песню / альбом / группу» в
  начале — подсказка типа, и из названий вроде «Группа крови» это слово не теряется.
- **Точное совпадение** — играет сразу.
- **Ничего общего** — Алиса говорит «Локально не найдено: X».
- **Точного нет, но есть похожие** (песни, в названии которых есть слово запроса, точно или в
  падеже) — Алиса спрашивает *«Точно такого нет. Нашла похожие песни: N. Включить их или
  поискать на Спотифай?»*, и колонка **сразу начинает слушать** (без «Алиса», 10 с): «включай /
  да» — играют похожие; «на Спотифай» — поиск в Spotify (артисты, песни, альбомы, выбор тем же
  строгим сопоставлением: артист > песня > альбом); «нет» — пауза и тишина. Собственный ответ
  Алисы на эти слова срезается.

Прослушивание без «Алиса» — метод **2 (startConversation)** канала `AliceCapability`. Номера
методов не опубликованы; восстановлены только чтением бинарника `maind` со Станции (typeinfo
лямбды → `std::function` с libc++ policy → константа в invoker) и сверены с известными:
0 startRequest, 1 cancelDialog, 2 startConversation, 3 stopConversation, 4 toggleConversation,
5 finishConversationVoiceInput, 6 cancelDialogAndClearQueue, 14 stopTts, 18 startVocalize,
19 startRecognize.

Запрос голосом играет один раз: перед запуском мост выключает повтор очереди (что делать, когда он
доиграл, решает Home Assistant — например, вернуться в плейлист диджея). «Пауза» запоминает трек и
секунду; «продолжи» перематывает туда, если Music Assistant начал трек с 0:00 (во flow-режиме так
бывает, если во время паузы говорила Алиса).

Проверка без воспроизведения: `POST http://<колонка>:8765/api/cmd` с телом `find <запрос>`
отвечает, что сыграл бы поиск (`OK …`, `SIMILAR …` или `NOT FOUND …`).

## Телевизор

Если настроен телевизор/проектор, «Алиса, найди в пубере / в кинопабе X на телевизоре» открывает
поиск в Android TV приложении Puber (kino.pub) через `puber://search?q=X`.

## Требования

- Яндекс-Станция с root + ADB и установленной [Luna](https://github.com/nyakokitsu/luna) через
  [YAM](https://github.com/nyakokitsu/yam) (проверено на Станции Мини 2, `yandexmini_2`).
- Home Assistant с интеграцией Music Assistant и `media_player` колонки, плюс долгоживущий токен.

## Сборка

Нужен Rust (rustup). Артефакты — в `dist/`.

```sh
sh scripts/build-arm.sh          # armv7 (Linaro, glibc ≤2.23) -> dist/soundya-armv7.tar

# Пакет Luna (.yampkg):
git clone https://github.com/nyakokitsu/yam ../yam
(cd ../yam && cargo build --release --bin yam-publish)
YAM_SRC=../yam YAM_PACK_ONLY=1 YAM_TARGETS=yandexmini_2 sh scripts/yam-release.sh
```

## Установка (пакетом Luna)

```sh
adb push dist/soundya-<версия>-yandexmini_2.yampkg /tmp/ma.yampkg
# Luna держит YAM-lock — на время установки её надо остановить:
ssh root@<колонка> '/etc/init.d/S99luna stop && \
  /data/yam/bin/yam-run install --yes /tmp/ma.yampkg && \
  /etc/init.d/S99luna start'
```

Два soundya одновременно нельзя (общий тап голоса, порт 8765, AirPlay) — ставить **вместо**
штатного soundya. Автономный путь из апстрима (`scripts/deploy.sh`) тоже работает — см.
[docs/README.upstream-soundya.md](docs/README.upstream-soundya.md).

## Настройка Music Assistant

Открой `http://<колонка>:8765/` → раздел **Music Assistant**:

- **Адрес Home Assistant** — напр. `http://homeassistant.local:8123`
- **Плеер колонки** — `media_player.*` колонки в MA/HA
- **Токен** — долгоживущий токен Home Assistant (хранится только на колонке, в UI маскируется)
- **Тип по умолчанию** и **Диджей (radio_mode)** — по вкусу

## Отличия от soundya

- `src/ma.rs` — **новый**: клиент REST Home Assistant, локальный индекс, вопрос о похожих,
  поиск на Spotify.
- `src/local.rs` — **новый**: сопоставление голосового запроса с библиотекой (падежи, транслит,
  скелет согласных, инициалы) и похожие песни.
- `src/alice.rs` — маршрутизация (музыка → MA по умолчанию, «саундклауд» → SoundCloud; транспорт
  за активным источником; `keyword_only` не применяется при включённом MA; генерик «включи
  музыку» → MA).
- `src/main.rs` — `Cmd::Voice(Intent, bool)`, `ma_intent`, `Shared.ma_enabled/ma_active`.
- `src/settings.rs` — `ma_enabled/ha_url/ha_token/ma_entity/ma_radio/ma_type`.
- `src/web.html` — карточка настроек Music Assistant.
- `src/{buttons,luna}.rs` — кнопки и команды Luna идут в активный источник.
- `src/tv.rs` — «найди в пубере X» → deep link `puber://search`.
- События речи Алисы принимаются и с меткой конверта 253=3, и с 253=210 (новые прошивки) —
  иначе конец речи не замечался и каждый `say` ждал 15 с.

Всё, что soundya умел раньше (SoundCloud голосом, AirPlay, ПК/ТВ, обход блокировок), сохранено.
